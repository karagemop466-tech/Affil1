Campaign ledger

An empty ledger,
with its columns defined

The brief asked for measurement before optimisation. The measurable unit here is a row, and a row needs a provenance note. There are none yet.

0 rows · 0 sessions · 0 clicks · 0 reported orders · no forecast

A ledger is only worth keeping if every row can be traced back to a report somebody was authorised to read. The columns below are therefore fixed in advance, and the rule is that a row is added only when the value comes from an authorised first-party report, with the date and the source recorded alongside it.

There are no rows. Not because the table was forgotten, but because no Associates report has been supplied, no analytics endpoint is live, and there is no traffic to measure. A table with six plausible numbers in it would be the most damaging thing this site could publish.

The provenance rule

  1. Date — the date of the report, not the date of entry.
  2. Source — which report, in which account, exported by whom.
  3. Channel — organic search, direct, referral or social, as the report labels it.
  4. Eligible sessions — sessions that had a reasonable chance to reach a link, not raw page views.
  5. Clicks — outbound clicks as recorded, not as estimated.
  6. Reported orders — orders the Associates report attributes, including ones later returned.
  7. Provenance note — one line a stranger could follow to check the row.

What is deliberately absent

No conversion rate. No revenue estimate. No commission projection. Each would require a rate card that has not been read, a traffic figure that has not been measured, and a conversion assumption with nothing behind it. The site says so instead of producing a number that looks like evidence.

What would put a row here

One test click, then one Associates report. That is it. Suggestion S-01.
