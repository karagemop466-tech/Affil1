Editorial desk · Choose before building

Suggestions for a more useful publication

This is the review surface for choosing what to build next. Each idea lists the reader need, the evidence it requires, the unknowns, and a low-risk way to discover them. None of the working titles is a popularity or search-volume claim.

Current recommendation: complete the product-link identity and tracking check first, then publish the four question-shaped guides already drafted, and only then use real Search Console queries to choose the next topic. This avoids writing product-specific claims before product identity is established.

Editorial paths to choose from

Reader decision: which form factor fits their cooking habits and space. Evidence needed: exact product identities, manufacturer dimensions/manuals, and sourced feature details if products are compared. Discovery: validate phrasing in Search Console after search impressions begin; interview a small number of target readers before adding claims about pain points. Risk: low if kept as a neutral checklist; high if it implies one style is superior without evidence.

Reader decision: whether usable capacity matches a household’s usual meals. Evidence needed: exact-model measurements and manufacturer explanation of capacity terms. Discovery: record actual Search Console queries and ask readers what units or dimensions are confusing. Risk: unsupported “serves X” claims; keep serving needs personal and the measurements model-specific.

Reader decision: whether the appliance fits daily kitchen routines. Evidence needed: manuals, placement/clearance rules, external dimensions, and care instructions. Discovery: compare Search Console queries with reader questions; no review mining or scraped data needed. Risk: do not invent dishwasher safety, coating, or ease-of-cleaning judgments.

Reader decision: whether additional modes earn the appliance’s space. Evidence needed: model manuals, exact included accessories, and documented function descriptions. Discovery: examine actual Search Console question queries once data exists; use a reader poll only if a privacy-compliant capture mechanism is separately approved. Risk: avoid saying features are high-performing without testing.

The choice is saved only in this browser’s local storage. It is not sent to a server and does not constitute measured audience demand.

More titles to test—not trend claims

  • “Will it fit where you cook? A countertop-appliance measuring guide” — a practical dimension-and-clearance cluster.
  • “Which air-fryer accessories deserve drawer space?” — a checklist for comparing included accessories and documented uses; requires exact model sources.
  • “Holiday hosting, one crowded counter: a kitchen-appliance planning checklist” — a seasonal editorial hypothesis, not a claim about seasonal search demand.

Evaluate titles against actual Search Console query data after it exists. These are editorial hypotheses only; no popularity or search volume is claimed.

Prioritized implementation suggestions

  1. Gate the outbound links. Complete the five-row intent and destination process in the register. Keep intent and observed redirect in separate fields.
  2. Keep the disclosure in the publishing template. Preserve the disclosure strip below the masthead and footer repetition on every route; review every recommendation/link context. Keep the affiliate disclosure clear and close to the recommendation; review the current FTC guidance for the context of each link.
  3. Publish the four useful guides. Improve them with official model-specific evidence only after exact products are confirmed. Update sitemap and RSS feed when new content is published.
  4. Connect analytics before optimization. The static site includes a defined event sender and standalone endpoint source, but the endpoint is not deployed on GitHub Pages. Configure a self-hosted endpoint and verify delivery before treating analytics as live.
  5. Measure Search Console. Verify ownership, submit sitemap, and wait for actual performance queries. No traffic results can be produced from repository data alone.
  6. Automate only reversible chores. Validate links, disclosure placement, metadata, and feed/sitemap membership in CI. Put product facts, claims, and publication decisions behind a human review gate.

How to rank a suggestion

Score each option from 1–5 for reader usefulness, evidence readiness, audience signal, compliance risk (reverse scored), and production effort (reverse scored). Write the evidence beside each score. If audience signal is missing, mark it “not measured” rather than assigning a zero or inventing a result. Choose the path with a real reader question and sufficient evidence—not a speculative commission forecast.
