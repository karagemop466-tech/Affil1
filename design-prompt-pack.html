The design prompt pack.

Everything needed to brief a redesign of this site — brand, layout, tokens, page inventory, editorial direction and the guardrails — in one place, so the next design pass is a decision, not a drift. Nothing on this page is implemented because it appears here; it is input to the suggestions queue.

Read first: this pack is gated on Q11–Q20 — especially Q11 (audience), Q12 (brand sign-off) and Q13 (imagery rights). Until those are answered, the prompt below is a proposal, not a spec.

1 · The copy-paste redesign brief

Paste the block below into your design tool of choice (or hand it to whoever reskins the site). It is deliberately self-contained and carries the compliance constraints with it.

You are the art director and front-end engineer for “Good Measure — Kitchen Notes”, an Amazon Associates publication about air fryers and multi-function kitchen appliances. It must read like a small, fiercely edited food-and-kitchen magazine — never like a generated affiliate farm.

BRAND
- Name: Good Measure — Kitchen Notes. Mark: lowercase “gm” in a sage rounded square. Tagline: “The Kitchen Edit”.
- Palette (tokens already in styles.css): ink #111827, paper #ffffff, base #fafaf6, line #e7e5e4, accent deep sage #3f6246 (hover #2f4a35), muted #4b5563, warn strip #fef3c7 on #78350f ink. Radius 12px. Max width 1100px. One serif/sans pairing, system fonts only — no external font requests.
- Voice: dry, generous, specific. Question-shaped headlines (“Basket or oven-style: what should you compare?”). No superlatives, no “best”, no “game-changer”, no fake urgency, no exclamation marks in headlines.

AUDIENCE (fill in Q11 before shipping)
- One reader. Someone cooking three to five nights a week in a small-to-medium Dutch kitchen (NL, with EU/UK/NL English readers), who wants fewer appliances used harder — and who distrusts round-ups.

INFORMATION ARCHITECTURE
- / (front page): disclosure strip; masthead; hero with original art + one-line promise; “This week’s picks” product grid (products-first, never verification-first); seasonal reading band; open questions strip; suggestions pointer; empty campaign ledger; “How we work” strip; footer with full sitemap + disclosure repeat.
- /guides/ (index) + /guides/<slug> (one question per guide, 400–700 words body + checklist).
- /products.html (register table), /dashboard.html (findings + ledger), /categories/air-fryers.html, /suggestions.html (decision queue), /questions.html (open-question register), /reviews/flagged.html + /reviews/verification-audit.html (transparency desk), /design-prompt-pack.html (this page), /disclosure.html, /privacy.html.
- One canonical URL per topic; duplicates redirect; sitemap.xml + rss.xml + feed.xml updated on every publish.

PRODUCT SURFACES (hard rules)
- No prices, ratings, review counts, stock or delivery promises — Amazon serves those only via a live feed we do not have.
- Every outbound product link: rel="sponsored nofollow noopener", opens in a new tab, and sits under an above-the-fold disclosure strip repeated in the footer.
- Intended vs observed identifiers are never merged. “Listing observed” (single point in time) is labelled as such; conflicts show both passes, never an average.
- No manufacturer images without confirmed media-kit rights; default to original illustration/photography.

EDITORIAL RULES
- Every product-specific factual statement must trace to (a) the seller listing title, (b) an official source, or (c) it is framed as a question for the reader. Otherwise omit it.
- Every guide ends with “before you buy” checklist and links internally only to canonical pages.
- Working titles carry “editorial hypothesis — not a claim about popularity, search volume or product superiority.”

PERFORMANCE & ACCESSIBILITY
- Budget: total page weight < 250 KB excluding the hero image; hero < 200 KB, width 1270, lazy-loaded below the fold. No third-party scripts. No cookies. Visible focus rings. prefers-reduced-motion respected. Colour contrast ≥ 4.5:1.

5 · Organic-traffic levers, in order of honesty-to-effort

  1. One canonical host + clean sitemap/feed/RSS — done and maintained; nothing can rank if engines see three duplicates of every page.
  2. Question-shaped titles mapped to the cluster — basket vs oven → capacity → cleanup → multi-function → gifting; each new guide links up and sideways, never orphaned.
  3. E-E-A-T signals — authorship (Q15), published/updated dates on every guide, sources block per guide, visible corrections policy (Flagged for Review page doubles as this).
  4. Search Console verification + 4–6 weeks of query data (Q14) — only then do H2–H6 get scheduled; until then they are hypotheses.
  5. RSS + feed auto-discovery — every page ships rel=alternate; the feed is the zero-cost distribution channel.
  6. No backlink schemes, no AI-spun volume — both violate the same quality bar Amazon and Google enforce from opposite sides.

6 · What this pack must never produce

  • Prices, ratings, review counts, “orders today: 132” — anything Amazon does not serve live.
  • “Best”, “#1”, “winner”, fake countdowns, invented expert quotes or credentials.
  • Outbound links without visible sponsored marking and rel="sponsored".
  • Manufacturer imagery without documented license; stock that looks like implied endorsement.
  • Merged intended/observed identifiers, or silence where passes disagree — show the disagreement.
