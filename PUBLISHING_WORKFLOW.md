# Publishing workflow — the gate, and what it cannot check

No page publishes until every check below passes. Half of them are enforced by
`tools/validate.py`, which runs in CI before the deploy job and again on a weekly
schedule; the other half are judgement and can only be performed by a person. The
split is stated explicitly, because a checklist that implies automation it does not have
is how a site ends up non-compliant while looking tidy.

Run locally before pushing:

```bash
python3 tools/build.py    # every page is generated from src/data — never edit HTML by hand
python3 tools/validate.py # the gate; non-zero exit blocks the deploy job
```

## 1 · Disclosure (enforced by the build)

- [x] The disclosure strip is generated by one template (`disclosure()` in `tools/build.py`),
      so a page cannot be built without it; it sits under the masthead, above the fold.
- [x] It repeats in the footer, with the fuller Associates statement.
- [x] The required sentence appears verbatim — *"As an Amazon Associate I earn from
      qualifying purchases."* — followed by a plain-language explanation, per Operating
      Agreement §5 and the FTC's "clear and conspicuous" standard.
- [x] `validate.py` fails a page whose strip appears after `<main>`.
- Source: <https://affiliate-program.amazon.com/help/operating/agreement> (retrieved 2026-11-20)
· <https://www.ftc.gov/business-guidance/resources/ftcs-endorsement-guides-what-people-are-asking>

## 2 · Links (enforced by the build)

- [x] Every outbound link a reader could buy through carries
      `rel="sponsored nofollow noopener"`, a visible "Paid link" note, and `target="_blank"`.
- [x] A buy button exists only where a product page was actually reached. An unresolved
      row gets a link to its flag entry instead — never a guess.
- [x] No tracking tag is published unless an account-validated Special Link is recorded in
      `src/data/product-intent.json`. `tools/check.py` fails the build if any Amazon product link
      is outside `tools/layout.py` `permitted_amazon_urls()` (an approved Special Link, or the
      plain listing of an observed ASIN). Until a Special Link is recorded every button is a
      labelled **reference link** to the official listing. The reading of Program Policies 2(b)
      behind this is an open owner decision (FLG-025).
      Rationale: an untagged redirect through an intermediate host cannot be attributed
      (Commission Income Statement §2(e), §2(g)), and a tag implies a registered site on an
      enrolled account, which this repository cannot verify.
- [ ] **Human step (one command, owner-only):** `python3 tools/arm_links.py --checklist`, then
      paste each Associates-generated Special Link with
      `python3 tools/arm_links.py --i-am-the-owner --link P-01 "<url>"`. One product first;
      confirm the click in the account's report before arming the rest.
      `tools/verify_links.py` reports destination drift; it cannot confirm attribution.

## 3 · Claims and endorsement context (human review)

- [ ] Read each new guide once for sentences that imply Amazon endorsement, hands-on
      testing, or a superiority claim. The automated checks cover structure, not truth.
- [x] Capability statements must quote the seller's listing title, attributed as such.
      The editorial rule is stated on `/about/#method` and inside every guide's closing note.
- [ ] If a real editor exists, add the name and two true biographical sentences to
      `/about/#who`. Until then the byline says "editorial desk", on purpose.
- Source: 16 CFR Part 255 · Associates Program Operating Agreement §5 (no misrepresentation
  of the relationship)

## 4 · Data and verification (partly enforced)

- [x] Facts live in `src/data/*.json`. Each product row carries the submitted link, the
      observed destination, the retrieval date, the source, and separate
      intended/observed identifier fields that are never merged (`validate.py` errors if
      `intended_asin` equals the observed ASIN).
- [x] No price, star rating, review count or availability string may appear anywhere:
      `validate.py` warns on any dollar-figure pattern in a page.
- [x] An unconfirmed value is left blank and listed on `/flagged/` with the source that
      would settle it. Never fill a blank with an estimate.
- [x] Every destination is stored with the timestamp and the arrival parameters it was
      observed under, including `plpRedirect=mhFallback` where Amazon served a fallback
      (`tools/verify_links.py` records and flags it; it never overwrites intent with observation).
- [ ] **Human step:** re-run `python3 tools/verify_links.py --write` where egress to
      amazon.com is permitted, and read the drift report before the next issue.
- Prohibited outright, recorded as rejected proposals so nobody "improves" them in: price
  tracking or price alerts, copied listing images, republished reviews or ratings, cached
  Program Content without a live feed. Source: Associates Program Participation
  Requirements / Program Policies.

## 5 · Navigation, findability, assets (enforced by the build)

- [x] One navigation group for readers; every register reachable from the footer and from
      `/dashboard/`.
- [x] Every internal link, image and asset resolves over HTTP at the Pages project mount
      (`tools/check_deploy_paths.py`), because root-absolute paths break under `/Affil1/`.
- [x] Exactly one `<h1>` per page; every `<img>` has `alt`; every canonical sits inside the
      published base; the feed's items all appear in the sitemap.
- [x] Sitemap and feed are regenerated in the same build, so a new guide is findable the day
      it is published, not "eventually".

## 6 · Measurement

- [x] The five defined events (`page_view`, `outbound_click`, `guide_read`,
      `suggestion_review`, `session_start`) are named in one place in
      `assets/js/events.js`, shared by the board and the source register, so the spec and
      the code cannot drift apart.
- [x] The client ships inert: it sends nothing until a first-party endpoint exists. No
      cookies, no IP capture, no third-party script.
- [ ] **Human step:** deploy `analytics/endpoint.py` (or an equivalent) somewhere with
      storage, point the client at it, and add a line to `/about/#privacy` describing what
      is stored. Then, and only then, does the campaign ledger accept rows — from
      authorized first-party reports, with provenance, and never a revenue forecast.

## 7 · Publish

- [ ] PR opened from the session branch to `main` with a summary, the sources consulted and
      anything flagged; CI green including the committed-output check.
- [ ] Merge; watch the `Deploy static site to GitHub Pages` run to completion; confirm the
      live URL serves the front page and one guide.
- [ ] Record the PR link, the deploy result and any irregularity in `COORDINATION.md`, on
      the board — not in a commit message only.
- [ ] If the gate fails, fix the data and rebuild. Do not merge a broken site, and do not
      relax a check to make it pass.
