Irregularities register

  1. IR-1 — Submitted codes are not ASIN-format identifiers. All five submitted codes are 9 characters. Amazon defines an ASIN as “a unique 10-character alphanumeric code assigned to every product listed in the Amazon store” (official definition, fetched 2026-11-20). They are short-link slugs. Field labels reading “Intended ASIN” should read “Submitted code (short-link slug)”. Action: relabel at integration; set intended ASINs only from submitter statements or Associates tracking reports.
  2. IR-2 — Same-date observations disagree for three of five links. See the discrepancy table. Amazon returns different responses to different clients and times, so a single observation does not establish a stable destination. Action: repeat observations with tools/verify_links.py; treat a destination as stable only after repeated agreement plus an Associates-workflow test.
  3. IR-3 — Observed destinations never match the submitted slug. In every resolved case the observed /dp/ code differs from the submitted code. Intent remains unconfirmed. Action: keep intended and observed fields separate; confirm intent via the test-one-link runbook.
  4. IR-4 — Landing-page variant varies by client. This pass landed on a mobile “Product summary” variant for all resolved links. Consumer-browser landing behavior is unverified. Action: operator clicks each link in a normal signed-in browser as part of the test-one-link runbook and records what renders.
  5. IR-5 — The register is not all air fryers. One observed listing is a wireless meat thermometer. Category framing that says “air fryers only” does not cover the register. Action: broadened naming requested at integration (owners of contested files to decide).
  6. IR-6 — Attribution and Special Link compliance unverified. Observed URLs carry tracking parameters of unknown provenance; tracking ID shopnow047c-20 is user-supplied and enrollment is unverified. The Agreement requires that links “properly use the special ‘tagged’ link formats we provide” (Operating Agreement, §1 and §5, fetched 2026-11-20). Action: test one link per product in the enrolled Associates workflow; confirm destination and tracking report before scaling. No claim of validity or invalidity is made.
  7. IR-7 — No prices, ratings or reviews recorded. Values seen during fetches could not be attributed to the observed listing with confidence; recording them would be inference. Action: populate only from Amazon-provided tools/data permitted by the Program Policies, with a dated source.

IR-8 — Multiple divergent register schemas exist. data/confirmations.json, data/products.json, archive/ copies and the crisp/ edition's data/product-intent.json use different schemas and status vocabularies for the same links.
