Read this before reading anything into a number

The client beacon makes no network request at all while CRISP_ENDPOINT is unset. Every count on this page is therefore zero because nothing is being measured — not because nobody clicked. Web Analytics are not connected either. Treat this page as a wiring diagram, not a report.

The endpoint contract

What a host has to implement, written down so the design cannot drift once someone deploys it:

RequirementDetail
AcceptsPOST of a JSON body: { e, p, d, t } where d is a date at day granularity.
StoresAn aggregate counter increment keyed by e, p.path or p.product_id, p.placement, and d.
Must not storeIP address, user agent, referrer string, cookies, or any request header that identifies a device.
Must not doIssue a redirect, set a cookie, or return anything the browser needs. The response is fire-and-forget.
RetentionDecided by the operator and stated publicly before the endpoint goes live. See open question Q-06.
PreconditionA published privacy notice naming the counter. See Q-09.

Why it is not a redirect

The obvious way to count an outbound click is to route it through /go/<id> and issue a 302. That design creates two problems the Associates policies speak to directly: purchases referred through an intermediate site that does not require an affirmative click are disqualified, and associates may not obscure the url of the site containing their links. A fire-and-forget beacon avoids both, because the reader's browser navigates to Amazon itself and the counter never touches the navigation.

The cost of that choice is honest to state: a blocked beacon under-counts, and the figure can never be reconciled exactly against Amazon's own session count. That is acceptable, because Amazon's reports are the only authoritative conversion source anyway.

What would make this real. Three things, in order: a host for the endpoint, a published privacy notice, then a retention period set and stated. Until all three exist the counter stays off, because a half-configured counter collects data someone has to be responsible for.
