FLG-001 high

Every submitted path code is 9 characters; every ASIN observed on arrival is 10

Expected
An Amazon Standard Identification Number is a 10-character alphanumeric identifier.
Found
All five submitted codes (B04G1MEwY, B02NbDxp3, B00hJ57DV, B0c8moW59, B0f3GKalj) are 9 characters and contain lowercase letters. All five destinations resolve and carry 10-character uppercase ASINs: B0CDY277D3, B09B7SB46R, B08DKYBTPH, B0DHZTCNR5, B0DZFD6R9Z.
How to read it
The submitted codes are short-link slugs rather than product ASINs. An earlier register on this repository mistakenly placed them in the intended ASIN column. That error is corrected here by keeping intended_asin null until the account owner confirms each ASIN.
What the site does about it
The 'intended_asin' field is null for all five rather than filled with the slug. Intended and observed identifiers are never merged.
Blocks
nothing — but it explains why the intended ASIN column stays blank until account-owner confirmation

Where to check it yourself

  • https://affiliate-program.amazon.com/help/operating/agreement
  • https://developer-docs.amazon.com/sp-api/docs/catalog-items-api-v2022-04-01-reference
  • Open each supplied link and compare the /dp/ segment to the 9-character code in the submitted link
FLG-002 high

No supplied link showed the tracking tag on arrival

Expected
Special Links must use the Associates ID assigned to the account (SRC-02).
Found
None of the five resolving links presented a tag parameter on the page that was reached. The tracking ID shopnow047c-20 was supplied in the brief but was not observed in any resolved URL.
How to read it
This is not proof the links are untagged — the tag may be applied server-side by the short-link service after the arrival page was captured. It is proof that this build could not confirm attribution, which is different.
What the site does about it
No page claims a click will be attributed. Every product page states that attribution is unconfirmed.
