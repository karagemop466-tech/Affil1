FLG-001 high

Every submitted path code is 9 characters; every ASIN observed on arrival is 10

Expected
An Amazon Standard Identification Number is a 10-character alphanumeric identifier.
Found
All five submitted codes (B04G1MEwY, B02NbDxp3, B00hJ57DV, B0c8moW59, B0f3GKalj) are 9 characters and contain lowercase letters. The four destinations that resolved carry 10-character uppercase ASINs: B0CDY277D3, B09B7SB46R, B08DKYBTPH, B0DZFD6R9Z.
How to read it
The submitted codes are most likely short-link slugs rather than identifiers. The earlier register on this repository treated them as intended ASINs, which is why its identity column was empty. That reading is corrected here.
What the site does about it
The 'intended_asin' field is null for all five rather than filled with the slug. Filling it with the slug would have been an inference.
Blocks
nothing — but it explains why the register looks emptier than expected

Where to check it yourself

  • https://affiliate-program.amazon.com/help/operating/agreement
  • Open each supplied link and compare the /dp/ segment to the code in the link
FLG-002 high

No supplied link carried the tracking tag in the URL the fetcher landed on

Expected
Special Links must use the Associates ID assigned to the account (SRC-02).
Found
All five supplied links were requested on 2026-11-20 and the final URL was recorded. None of the five final URLs contained a tag parameter; each ended in a /dp/ASIN address. A redirector can apply attribution server-side, so this is an observation about the visible URL, not proof that the links are untagged.
How to read it
Attribution cannot be confirmed from the reader's side. The site therefore does not rely on the short links: every outbound product link is built from the observed ASIN plus ?tag=shopnow047c-20, which is what Program Policies 2(b) asks for. See FLG-016.
What the site does about it
No page claims a click will be attributed. The site says attribution is unconfirmed.

FLG-016 high

Earlier builds linked to bare /dp/ addresses with no Associates tag

Expected
Program Policies 2(b): 'you must include your Associates ID or "tag" ... as a parameter in the URL of each link you place on your Site to an Amazon Site.'
Found
The product links in the previous build were https://www.amazon.com/dp/ASIN with no tag parameter. A click through one could not carry an Associates ID in the URL, so it was not a Special Link as the policy defines one.
How to read it
Fixed in this build: every outbound product link is now the observed ASIN plus ?tag=shopnow047c-20, marked rel="sponsored nofollow noopener", and opens in a new tab. The bare listing URL is still recorded, in a separate field, so the difference stays visible.
What the site does about it
Affects whether a click can earn at all. Fixed, but unconfirmed until one click appears in the Associates report.
Blocks
