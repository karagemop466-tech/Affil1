FLG-001 high

Every submitted path code is 9 characters; every ASIN observed on arrival is 10

Expected
An Amazon Standard Identification Number is a 10-character alphanumeric identifier.
Found
All five submitted codes (B04G1MEwY, B02NbDxp3, B00hJ57DV, B0c8moW59, B0f3GKalj) are 9 characters and contain lowercase letters. All five destinations now resolve and carry 10-character uppercase ASINs: B0CDY277D3, B09B7SB46R, B08DKYBTPH, B0DHZTCNR5, B0DZFD6R9Z (P-04 resolved on re-verification 2026-11-20; earlier checkpoint-only outcome preserved in resolution_note).
How to read it
The submitted codes are most likely short-link slugs rather than identifiers. The earlier register on this repository treated them as intended ASINs, which is why its identity column was empty. That reading is corrected here.
What the site does about it
The 'intended_asin' field is null for all five rather than filled with the slug. Filling it with the slug would have been an inference.
Blocks
nothing — but it explains why the register looks emptier than expected

Where to check it yourself

  • https://affiliate-program.amazon.com/help/operating/agreement
  • Open each supplied link and compare the /dp/ segment to the code in the link
FLG-002 high

No supplied link showed the tracking tag on arrival

Expected
Special Links must use the Associates ID assigned to the account (SRC-02).
Found
None of the five resolving links presented a tag parameter on the page that was reached. The tracking ID shopnow047c-20 was supplied in the brief but was not observed in any resolved URL.
How to read it
This is not proof the links are untagged — the tag may be applied server-side by the short-link service after the arrival page was captured. It is proof that this build could not confirm attribution, which is different.
What the site does about it
No page claims a click will be attributed. The site says attribution is unconfirmed.
Blocks
any revenue expectation

Where to check it yourself

  • https://affiliate-program.amazon.com/help/operating/policies
  • One click from the owner's device, then the Associates click report
FLG-004 high

P-04 could not be resolved at all

Expected
A short link resolves to a product page.
Found
https://link.amazon/B0c8moW59 was requested three times on 2026-11-20. Each request returned Amazon's /checkpoint/continue interstitial. No product page was reached, so no product, brand, category or ASIN was recorded.
How to read it
Could be an expired link, a typo, a region restriction, or a challenge specific to this client. It was not diagnosed.
What the site does about it
P-04 has no card, no photograph and no buy link. It appears only in the register as an unresolved row.
Blocks
the fifth product

Where to check it yourself

  • Open https://link.amazon/B0c8moW59 in a normal browser and note where it lands
FLG-003 medium

Compliance status of the short links is unresolved, not disproven

Expected
Special Links may be created by the Associate or supplied by Amazon, and must include the tag as a URL parameter (SRC-02).
Found
The supplied links are of the form link.amazon/<code>. This build could not establish whether that form is an Amazon-issued redirect that applies the tag itself or an untagged redirect.
How to read it
An earlier version of this site implied the links were unusable. That was an overstatement. The honest status is unknown.
What the site does about it
The links remain on the site, marked sponsored, with attribution described as unconfirmed.
Blocks
nothing

Where to check it yourself

  • https://affiliate-program.amazon.com/help/operating/policies
FLG-005 medium

No price, rating, review count or stock status — by rule, not by omission

Expected
Program Policies §2(b) permit price and availability only where Amazon serves the data or it arrives via Creators API / PA API.
Found
Neither path is connected.
How to read it
This is the single most common failure in affiliate sites and the most common way an Associates account is closed. Empty is the compliant state.
What the site does about it
A machine check in tools/check.py fails the build if a currency figure, a star rating, a review count or a stock phrase is introduced.
Blocks
nothing — the site is deliberately usable without them

Where to check it yourself

  • https://affiliate-program.amazon.com/help/operating/policies
FLG-006 medium

No author, and no basis for editorial authority

Expected
A publication a reader can assess.
Found
No byline. No first-hand testing. No credential.
How to read it
The guides are therefore written as checklists of questions, which is what can honestly be produced without access to the products. That is a real limitation on how much a reader should take from them.
What the site does about it
Every guide says plainly that no product was tested.
Blocks
the site's authority ceiling

Where to check it yourself

FLG-007 medium

Every photograph on this site is AI-generated illustration

Expected
Product photography would normally be real.
Found
All eight images were generated for this build. None is a photograph of a submitted product. Each is labelled where it appears.
How to read it
Unlabelled AI imagery next to a buy button is a deceptive practice risk. Labelled, it is an editorial convention. The line between the two is thin, which is why every use carries a caption.
What the site does about it
Captions read 'Illustration, not a photo of this product'.
Blocks
nothing, but it caps how persuasive a product page can be

Where to check it yourself

  • review/images.html lists every asset, its prompt intent, and every page it appears on
FLG-008 medium

The commit history says these files were deleted; the repository says they never existed

Expected
A repository whose history matches its contents.
Found
The root commit (76d898b) contains a nine-page site (Good Measure Kitchen). The working tree of this branch at start contained the same nine pages. A coordinated review of the other open branches on this repo found one that independently reached the same four ASIN resolutions recorded here, and another that shipped an analytics client and a self-hosted collector.
How to read it
Multiple agent sessions are working the same brief on parallel branches. This branch rewrote the site from the root rather than merging those branches, because they conflict structurally (one uses root-absolute links that break on a project Pages path; both define a different brand). Their verification results are cited where they agree with what was independently observed here.
What the site does about it
No other session's branch was deleted, force-pushed or modified.
Blocks
nothing

Where to check it yourself

  • https://github.com/karagemop466-tech/Affil1/pulls?q=is%3Apr
FLG-009 low

The site lives on a repository subpath, which changes how every link must be written

Expected
A site at a domain root can use /guides/ style links.
Found
GitHub Pages serves this repository at /Affil1/. A root-absolute link such as href="/about/" resolves to karagemop466-tech.github.io/about/ and 404s.
How to read it
This is the single most common way a project-pages site ships broken. Every internal link in this build is relative, and the checker resolves each one against the page's own directory.
What the site does about it
tools/check.py fails the build on any root-absolute internal href.
Blocks
nothing

Where to check it yourself

  • https://docs.github.com/en/pages
  • tools/check.py link resolution
FLG-010 low

Analytics exists in the code but is switched off

Expected
Measurement before optimisation.
Found
A client-side collector for the five defined events is in assets/js/analytics.js. It writes to sessionStorage only and sends nothing until a window flag is set. There is no endpoint deployed.
How to read it
Shipping a live analytics beacon without a privacy notice would be worse than shipping none. It is deliberately inert.
What the site does about it
The site currently measures nothing. Every traffic statement on this site says so.
Blocks
evidence-based iteration, and it is flagged as such

Where to check it yourself

  • review/measurement.html
