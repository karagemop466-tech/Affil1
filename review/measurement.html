Measurement plan

Measurement is written,
and switched off

Five events are defined, a client exists, and nothing is being recorded. That is the current state and it is deliberate.

Beacon disabled by default · no cookies · no third-party requests · no endpoint deployed

The brief asked for a privacy-preserving outbound-click counter and a self-hosted analytics endpoint. The client exists in this repository, records the five canonical events from _src/data/events.json, and is inert: nothing is recorded until a page sets an endpoint. The naming mismatch with the legacy event set (the five names in assets/js/analytics.js when this was written) is resolved — _tools/check.py now enforces the canonical five and fails on the legacy names. FLG-016 lists the legacy duplicates for review.

The client writes to sessionStorage to keep one page view from being counted twice in a single tab, and sends nothing. It has no cookie, sets no identifier that persists across days, and contacts no third party. It is switched on by setting one flag on the page, and switching it on without an endpoint and a notice would be a mistake.

What would be measured

EventFires whenWhat is stored
page_viewEvery page loadCounts a visit. Stores the path only, never a query string, so nothing typed into a URL is kept.
outbound_product_clickA reader activates an outbound link to a product listingRecords the product reference clicked (the ASIN from the destination) and the page it was clicked from. It is counted before navigation, so it does not prove a purchase or a commission.
guide_read_75A reader reaches 75% of a guideSeparates readers who actually read a guide from those who merely open it, which changes what the next guide should be.
compare_viewThe comparison page or a comparison table is renderedCounts how often the side-by-side view is entered, so the design question is answered from data, not instinct.
flag_page_viewThe Flagged for Review page is openedTells us whether the verification work is actually consulted, which tells us if it is visible.

What has to happen before it goes live

  1. A privacy notice. What is collected, why, for how long, and who to contact. This does not exist yet.
  2. A deployed collector. The endpoint is in this repository and is not hosted anywhere. GitHub Pages serves static files only.
  3. A retention decision. Raw event rows have a half-life; the ledger does not. A retention period has to be chosen, not defaulted.
  4. A consent decision. Whether visitor consent is required depends on jurisdiction and on what is collected. That is a legal question, not an engineering one, and it has not been answered.

Why the site currently claims nothing about traffic

Every traffic statement on this site is an absence: no sessions, no clicks, no conversions, no revenue. That is not modesty. With the beacon off, the site genuinely has no numbers, and inventing plausible ones would be the single fastest way to make everything else on the site untrustworthy.

What the campaign ledger holds

Nothing. It has a defined schema — date, source, channel, eligible sessions, clicks, reported orders — and every row has to arrive with a provenance note. See the empty ledger.
